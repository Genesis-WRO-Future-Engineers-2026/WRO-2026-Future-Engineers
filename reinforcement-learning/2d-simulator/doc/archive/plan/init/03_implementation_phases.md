# 実装フェーズとマイルストーン

## Phase 1: 基盤構築（2-3週間）

### 目標
2Dシミュレーター環境の基礎を構築し、手動制御で動作確認できる状態にする。

### タスク一覧

#### Week 1: 環境セットアップと基本構造
1. **プロジェクト初期化** (1日)
   - ディレクトリ構造の作成
   - `requirements.txt`の作成
   - `.gitignore`の設定
   - 初期テストの作成

2. **Box2D物理エンジンの統合** (2-3日)
   - `src/physics/box2d_wrapper.py`の実装
   - 車両の基本物理モデル作成
   - 摩擦、慣性、モーター力の実装
   - 単体テストの作成

3. **車両モデルの実装** (2-3日)
   - `src/env/vehicle.py`の実装
   - ステアリング、スロットル制御
   - 車両パラメータ（質量、サイズ、最大速度）
   - 車両状態の取得（位置、速度、角速度）

#### Week 2: センサーとコース
4. **LiDARセンサーシミュレーション** (3-4日)
   - `src/env/sensors.py`の実装
   - レイキャスティングによる距離測定
   - 5度刻み、72方向のスキャン
   - センサーノイズの基本実装
   - 可視化機能

5. **コースシステム** (2-3日)
   - `src/env/course.py`の実装
   - JSON形式のコース定義
   - 壁の定義（ポリゴン）
   - スタート/ゴール位置
   - シンプルな楕円コースの作成

6. **Pygameレンダラー** (1-2日)
   - `src/env/renderer.py`の実装
   - 車両、壁、LiDARスキャンの描画
   - リアルタイム表示
   - デバッグ情報の表示

#### Week 2-3: Gym環境統合
7. **Gym互換環境** (2-3日)
   - `src/env/minicar_env.py`の実装
   - `reset()`, `step()`, `render()`メソッド
   - 行動空間・観測空間の定義
   - 基本的な報酬関数

8. **手動制御テスト** (1日)
   - キーボード入力での車両制御
   - 動作確認スクリプト作成
   - パラメータチューニング

### マイルストーン: Phase 1完了条件
- [ ] 手動制御でコースを走行可能
- [ ] LiDARスキャンが正確に機能
- [ ] Pygameで可視化できる
- [ ] Gym互換インターフェースが動作
- [ ] 基本的なテストがパス

---

## Phase 2: 強化学習統合（2-3週間）

### 目標
PPOアルゴリズムを実装し、基本的な走行を学習できる状態にする。

### タスク一覧

#### Week 3: ニューラルネットワーク
1. **ポリシーネットワーク** (2-3日)
   - `src/rl/policy.py`の実装
   - 観測→行動のマッピング
   - 連続行動空間（Gaussian policy）
   - 正規化レイヤーの追加

2. **価値関数ネットワーク** (1-2日)
   - `src/rl/value.py`の実装
   - 状態価値の推定
   - ポリシーと共通のエンコーダ（オプション）

3. **経験バッファ** (1日)
   - `src/rl/buffer.py`の実装
   - 軌跡の保存
   - GAE（Generalized Advantage Estimation）
   - バッチサンプリング

#### Week 4: PPOアルゴリズム
4. **PPOコア実装** (3-4日)
   - `src/rl/ppo.py`の実装
   - クリッピング損失関数
   - エントロピーボーナス
   - 価値関数損失
   - 勾配更新ロジック

5. **学習ループ** (2-3日)
   - `src/rl/trainer.py`の実装
   - エピソード収集
   - PPO更新の実行
   - チェックポイント保存
   - 学習の安定化（報酬正規化等）

6. **TensorBoard統合** (1日)
   - `src/utils/logger.py`の実装
   - 報酬、損失のロギング
   - ネットワークパラメータの可視化
   - エピソード長の追跡

#### Week 5: 初期学習と調整
7. **基本報酬関数の実装** (2日)
   - 前進報酬（速度ベース）
   - 壁衝突ペナルティ
   - 時間ペナルティ
   - ゴール報酬

8. **ハイパーパラメータ調整** (2-3日)
   - 学習率、バッチサイズ等の調整
   - 報酬スケールの調整
   - エピソード長の最適化

9. **学習スクリプト** (1日)
   - `scripts/train.py`の作成
   - コマンドライン引数の実装
   - 設定ファイルの読み込み

### マイルストーン: Phase 2完了条件
- [ ] シンプルなコースで完走可能（成功率50%以上）
- [ ] PPOアルゴリズムが収束
- [ ] TensorBoardで学習過程を確認可能
- [ ] 学習時間が1-2時間以内

## Phase 3: 高度な機能（2-3週間）

### 目標
カリキュラム学習、Domain Randomization、ショートカット学習を実装。

### タスク一覧

#### Week 6: カリキュラム学習
1. **カリキュラムマネージャー** (2-3日)
   - `src/curriculum/curriculum_manager.py`
   - 難易度レベルの定義
   - 自動難易度調整
   - 複数コースの管理

2. **報酬シェーピング** (2日)
   - `src/curriculum/reward_shaping.py`
   - 段階的な報酬調整
   - チェックポイントシステムの実装
   - 壁接近ペナルティの動的調整

3. **複数コースの作成** (1-2日)
   - 易しいコース（wide_oval.json）
   - 中難易度（narrow_oval.json）
   - ショートカット付き（shortcut_1.json）

#### Week 7: Domain Randomization
4. **物理パラメータのランダム化** (2-3日)
   - `src/domain_randomization/physics_randomizer.py`
   - 摩擦係数のランダム化
   - 質量・慣性のランダム化
   - モーター応答遅延のランダム化

5. **センサーノイズ** (1-2日)
   - `src/domain_randomization/sensor_noise.py`
   - LiDARノイズの追加
   - IMUノイズのシミュレーション

6. **統合と学習** (2-3日)
   - Domain Randomizationを有効にした学習
   - パラメータ範囲の調整
   - 学習の安定性確認

#### Week 8: ショートカット学習
7. **チェックポイントシステム** (2-3日)
   - コース進行度の正確な計算
   - 複数ルート対応
   - ショートカット検出

8. **ショートカット報酬** (1-2日)
   - ショートカット通過ボーナス
   - リスク・リターンのバランス調整

9. **複雑なコースでの学習** (2-3日)
   - ショートカット付きコースでの学習
   - 報酬パラメータの微調整
   - エージェントの行動分析

### マイルストーン: Phase 3完了条件
- [ ] カリキュラム学習が機能（易→難への自動遷移）
- [ ] Domain Randomizationで学習が収束
- [ ] ショートカットを活用して走行
- [ ] 複数コースで高い成功率（80%以上）

## 全体スケジュール

```
Week 1-2:  Phase 1 - 基盤構築
Week 3-5:  Phase 2 - 強化学習統合
Week 6-8:  Phase 3 - 高度な機能
Week 9-10: Phase 4 - 検証と最適化
```

**総期間: 8-10週間**

## リスクとバッファ

### 想定リスク
1. **PPOの学習が不安定**: 報酬設計の見直し、ハイパーパラメータ調整（+1週間）
2. **物理パラメータの調整難航**: 実機データを先に取得（+1週間）
3. **ショートカット学習が困難**: 報酬関数の抜本的見直し（+2週間）

### バッファ期間
- 各フェーズに1週間の予備期間を設定
- 合計で2-3週間のバッファ

## 次のステップ

Phase 1完了後、以下を実施：
1. 動作デモ動画の作成
2. 初期結果の共有
3. Phase 2への移行判断
