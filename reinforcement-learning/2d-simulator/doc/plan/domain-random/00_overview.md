# Domain Randomization実装計画 - 概要

## 1. 目的

シミュレーターで学習したポリシーを実機に転移する際の**Sim2Real Gap（シミュレーションと実機のギャップ）**を軽減するため、Domain Randomizationを実装します。

### Sim2Real Gapの主要因

1. **物理パラメータの違い**
   - 摩擦係数の変動（床面の状態、ホコリ、湿度）
   - 質量のばらつき（バッテリー残量、パーツの取り付け誤差）
   - 慣性モーメントの差
   - モーター出力の個体差・電圧変動

2. **センサーノイズ**
   - LiDARの測定誤差（±2cm程度）
   - ドロップアウト（一部のレイが無効）
   - スパイクノイズ（外れ値）
   - 測定遅延（レイテンシ）

3. **制御系の違い**
   - モーター応答遅延（PWM制御の立ち上がり時間）
   - 通信遅延（Raspberry Pi ↔ モータードライバ）
   - 離散時間制御のサンプリング周波数

## 2. Domain Randomizationの効果

### 2.1 原理

学習時に物理パラメータとセンサーノイズをランダム化することで、エージェントは**幅広い環境条件に対応できるロバストなポリシー**を獲得します。

```
シミュレーション環境のパラメータ空間を広げる
    ↓
実機の真のパラメータがその範囲内に含まれる確率が上がる
    ↓
実機でも同様のパフォーマンスを発揮
```

### 2.2 期待される効果

| 効果 | 詳細 |
|------|------|
| **汎化性能の向上** | 未知の環境条件でも安定した走行 |
| **センサーノイズ耐性** | LiDARの測定誤差に対応 |
| **物理変動への適応** | 床面の変化、バッテリー残量に依存しない |
| **実機転移の成功率向上** | シミュレーション学習のみで実機走行可能 |
| **再学習の必要性削減** | 実機での微調整が不要またはわずかで済む |

## 3. 実装範囲

### 3.1 物理パラメータのランダム化

| パラメータ | 現在値（固定） | ランダム化範囲 | 理由 |
|-----------|-------------|-------------|------|
| **摩擦係数** | 0.7 | 0.5 ~ 1.0 | 床面の状態変動（ホコリ、湿度） |
| **質量** | 1.4 kg | 1.2 ~ 1.6 kg | バッテリー残量、パーツ誤差 |
| **慣性** | 自動計算 | ×0.8 ~ ×1.2 | 質量分布のばらつき |
| **モーター力** | 20.0 N | 18.0 ~ 22.0 N | 個体差、電圧変動 |
| **応答遅延** | 0 ms | 0 ~ 50 ms | PWM制御の立ち上がり時間 |
| **線形減衰** | 0.5 | 0.4 ~ 0.6 | 空気抵抗の変動 |
| **角減衰** | 0.8 | 0.6 ~ 1.0 | 回転抵抗の変動 |

### 3.2 センサーノイズのランダム化

| ノイズタイプ | パラメータ | 推奨値 | 目的 |
|------------|---------|--------|------|
| **ガウシアンノイズ** | noise_level | 0.01 ~ 0.02 | 測定誤差（距離の1-2%） |
| **ドロップアウト** | dropout_prob | 0.02 ~ 0.05 | レイの無効化（2-5%） |
| **スパイクノイズ** | spike_prob | 0.005 ~ 0.01 | 外れ値（0.5-1%） |

### 3.3 環境の多様化（既存機能）

- **コースバリエーション**: 壁位置のノイズ（±5cm）
- **カリキュラム学習**: 複数難易度のコース

## 4. 実装アーキテクチャ

### 4.1 モジュール構成

```
src/domain_randomization/
├── __init__.py
├── physics_randomizer.py    # 物理パラメータのランダム化
├── sensor_noise.py           # センサーノイズの統合（既存機能の活用）
└── config.py                 # デフォルト設定

src/env/
└── minicar_env.py            # Domain Randomizationの統合

scripts/rl-training/
└── train.py                  # コマンドライン引数の追加
```

### 4.2 データフロー

```
エピソード開始
    ↓
PhysicsRandomizer.randomize()
    ├─ 摩擦係数をランダム化
    ├─ 質量をランダム化
    ├─ モーター力をランダム化
    └─ 応答遅延をランダム化
    ↓
MinicarEnv.reset()
    └─ ランダム化されたパラメータで車両を初期化
    ↓
各ステップでLiDARスキャン
    ↓
SensorNoise.apply()
    └─ ガウシアン + ドロップアウト + スパイクノイズ
    ↓
観測データとして返す
```

## 7. リスクと対策

### 7.1 想定リスク

| リスク | 影響 | 対策 |
|--------|------|------|
| **学習が収束しない** | 高 | ランダム化範囲を段階的に拡大 |
| **パフォーマンス低下** | 中 | ノイズレベルを調整、カリキュラム学習と併用 |
| **実機で効果が出ない** | 高 | 実機データを取得してパラメータ範囲を調整 |
| **計算コスト増加** | 低 | 軽量な実装、キャッシュの活用 |

### 7.2 段階的導入戦略

```
Stage 1: センサーノイズのみ（軽微）
    ↓ 動作確認
Stage 2: 物理パラメータの一部（摩擦、質量）
    ↓ 学習の安定性確認
Stage 3: すべてのパラメータ（モーター遅延含む）
    ↓ 実機転移テスト
Stage 4: パラメータ範囲の最適化
```
